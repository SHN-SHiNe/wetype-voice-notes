## 1. 这是什么

微信输入法把每次「AI 录音笔」会话存在本机一个加密库里（`VoiceSummary`）。这套东西做两件事：

1. 用当前 Windows 用户的 DPAPI 解出密钥，解密索引、逐字稿、AI 纪要；
2. 按记录导出成可读文件，并做增量更新（只写有变化的内容）。

**范围：只拉取、只导出。** 不总结、不润色、不翻译、不合并逐字稿；需要分析另起任务，导出文件保持原样。

### 现状

2026-10-31 实跑 `status-hook.ps1` 的真实输出（PID、时间会变）：

```text

WeTypeVoiceNotesHookBackup  Ready  上次 10-31 15:00:00  结果 0x00000000（0）  下次 10-31 15:30
常驻 watcher：PID 24416  启动 10-31 11:15:09
结论：钩子已安装，watcher 正常运行。
```

同一天默认导出实测：**0 新增 / 0 更新，全部跳过**，没有改动任何文件的 mtime；索引里的记录要么已导出、要么是空壳，没有待导出项。条数会随录音变化，**以 `status-hook.ps1` 的「已导出记录」和 `--list` 末行为准，本文不写死**。

## 3. 三种取数方式

严格说**导出只有两条路径**：A 界面手工、B 命令行批量；C 是把 B 挂到计划任务上自动跑。

| 方式 | 适合 | 会留档吗 | 能批量吗 |
|---|---|---|---|
| A 图形界面 | 临时取一条、马上要文字 | 否，只到剪贴板/分享 | 否，逐条 |
| B 命令行 | 补跑、核对、换机器、脚本消费 | 是，四类文件 | 是 |
| C 自动钩子 | 日常默认，无感归档 | 是 | 自动 |

### A. 图形界面手动导出

适合「现在就要这一条的原文」，不产生本地档案。

1. 打开微信输入法，在状态栏/托盘里点「AI 录音笔」（窗口标题是「录音笔」）。
2. 左栏记录列表选一条；右侧是微信输入法自己生成的纪要。
3. 右上角「原文」进入「转写原文」页。
4. 右上角「复制」复制逐字稿；左上角「返回」回到纪要。
5. 纪要页右上角「分享」按客户端版本提供图片/链接等选项，**具体以界面为准**。

局限：逐条手工；复制出来的文字不落档，下次还得再来一遍；空壳记录打开也没有内容。界面文案可能随版本变化，按位置找即可。

### B. 命令行批量

```powershell
py -3 C:\Users\SHiNe\.dsh\skills\wetype-voice-notes\scripts\wetype_notes.py
```

默认就是增量、安静、可反复跑；只写有变化的东西。

| 参数 | 作用 | 备注 |
|---|---|---|
| `--list` | 打印记录清单（时间、时长、字数、状态、标题）后退出 | 不写任何文件 |
| `--out <目录>` | 导出根目录 | 默认 `C:\Users\SHiNe\Desktop\微信输入法录音笔导出` |
| `--force` | 忽略比较，全部重写 | 会改 mtime，**不要当「刷新」用** |
| `--json` | stdout 输出 JSON 摘要（计数、字数、新增项、孤儿目录） | 给程序/钩子消费 |
| `--open` | 完成后在资源管理器打开导出目录 | 不影响导出 |
| `--src <目录>` | 指定数据目录 | 默认 `VoiceSummary`；只在测试/迁移副本上用 |
| `--selftest` | 自检 AES 已知答案、CTR 往返、DPAPI、索引解密 | 不碰导出目录；密钥只打印长度 |

**退出码**（钩子按非 0 判失败）：

| 码 | 含义 |
|---|---|
| `0` | 成功，包括「0 新增 / 0 更新」 |
| `2` | 数据目录、`key.dpapi` 或 `index.json.enc` 缺失 |
| `3` | 解密失败：DPAPI、魔数不对、索引不是合法 JSON |

**增量与「相同内容不重写」**：是否重写由**磁盘上的现有文件**决定，不看状态文件。逐字稿/纪要逐字节比较；`meta.json` 只比较语义字段；`recap.docx` 只在纪要变化、缺失或被 `--force` 时重写。所以「跳过」是正确结果，mtime 不变；状态文件只是变更审计，不是判断依据。

运行摘要长这样：`新增 N 条 / 更新 M 条 / 跳过 K 条 / 空壳 J 条（索引共 T 条）`。`0 新增 / 0 更新` 就是没有新内容，不要用 `--force` 去「凑」一次写入。

**有正文的记录产出四类文件：**

- `transcript.txt`：逐字稿原文，UTF-8，不做任何整理。
- `recap.html`：客户端原始 AI 纪要（完整 HTML，含 CSS/SVG），浏览器直接打开。
- `recap.docx`：Word 重排版；需要 `python-docx`（本机已装）。SVG 矢量图进不了 Word，精确排版看 `recap.html`。
- `meta.json`：至少有 `summary_id`、标题、时间、时长、字数；`05` 起还有 `enc_dir` / `exported_by` / `exported_at`，`01–04` 是首版手工导出的旧字段（`has_recap` / `voice_id` / `source_enc`）。

另外会重新生成 `index.md`，并更新 `.wetype-export-state.json`。

### C. 自动归档钩子

本机默认已安装，不依赖 DSH 会话；关掉所有聊天窗口也照跑。它是**两个当前用户级计划任务**：

| 计划任务 | 触发 | 行为 |
|---|---|---|
| `WeTypeVoiceNotesHook` | 登录后延迟 30 秒 | 常驻 watcher（隐藏窗口），失败每分钟重启，单实例 |
| `WeTypeVoiceNotesHookBackup` | 每 30 分钟 | 跑一次 `watcher.ps1 -Once`，补上睡眠/退出期间漏掉的事件 |

- **20 秒去抖**：客户端分片写盘，钩子等最后一次写盘后静默 20 秒再导出；一条录音只导一次。
- 只有**新增/更新**才写日志、弹 Windows 通知、刷新 `最近一次同步.txt`；`0 新增 / 0 更新` 静默（加 `-LogAllRuns` 才记录）。
- 失败隔离：导出报错 15 秒后重试一次，仍失败就记日志并继续监视；后备任务兜底。

| 命令 | 作用 |
|---|---|
| `pwsh -File C:\Users\SHiNe\.dsh\skills\wetype-voice-notes\scripts\install-hook.ps1` | 安装/覆盖两个任务；加 `-Start` 立即启动 |
| `pwsh -File C:\Users\SHiNe\.dsh\skills\wetype-voice-notes\scripts\status-hook.ps1` | 任务状态、上次结果、watcher 进程、最近 5 条日志；退出码 `0` 正常 / `2` 已注册但进程没跑 / `1` 未安装 |
| `pwsh -File C:\Users\SHiNe\.dsh\skills\wetype-voice-notes\scripts\uninstall-hook.ps1` | 删两个任务、停进程、清隐藏启动器；**导出文件一个不动** |

只有换机器、改导出路径、任务丢了才需要重装。测试去抖时 `-Source` 必须指向**副本**，不要对着真实 `VoiceSummary` 造数据。

| 根目录文件 | 作用 | 谁维护 |

| `NOTES.md` | 解密格式、历史方法与同步摘要 | 人可写；只有 `<!-- WETYPE-SYNC:BEGIN -->` 区块被覆盖 |

| `最近一次同步.txt` | 时间、结果、新增/更新清单、日志路径 | 钩子；只在有新增/更新时刷新 |
| `NN_YYYY-MM-DD_标题\` | 单条记录的四类文件 | 工具 |

目录序号按 `created_at` 升序。**目录名取首次导出时的标题，之后标题变了也不改名**——所以 `index.md` 的标题和目录名可能不一致，例如 `07` 的目录还是旧标题「CC Switch-skills…」，`10` 的目录名是一长串转写开头；这是正常的。映射靠 `meta.json` 里的 `summary_id`，改目录名不会丢内容，但 `index.md` 链接和状态文件会暂时对不上，没必要改。

**历史遗留（可忽略）**：根目录的 `_plain\`（4 条明文副本 + 原始 `index.json`）、`_scripts\`（初版 `decrypt.ps1` / `export.py`）、`2026_10_27_建档自动化讨论_*`（另一份独立文档）都不是现行工具产物。现行脚本不读、不写、不删；`_plain` 是明文，注意隐私，确认没用了可自行清理。

## 5. 解密原理

只记结论，够你判断「是不是格式变了」；验证细节在 `NOTES.md` §1。

- **密钥**：`key.dpapi` = `WTVSKEY1`(8 B) + 原始 DPAPI blob。**去掉前 8 字节**后直接 `CryptUnprotectData`（CurrentUser 作用域、无 entropy），得到 32 B AES-256 密钥。不要把前 8 字节改写成 `cbData/dwVersion`，那会破坏 DPAPI 的 HMAC。
- **数据文件**：`WTVSAES1`(8) + nonce(12) + 16 B 未用字段 + 密文；算法是 **AES-256-CTR**（不是 GCM）。计数器块 = `nonce || BE32(块号)`，块号**从 2 开始**。
- 空壳记录的两个 `.enc` 都是 36 B = 8 + 12 + 16 + 0，没有正文。
- 那 16 B 字段用途未确认，不参与解密；格式本身**没有完整性校验**。状态文件里的 sha256 只做变更审计，不要拿它当真实性证明。
- `index.json` 解出是 JSON；`transcript.txt` 是 UTF-8 文本；`recap.html` 是完整 HTML。

README 不贴密钥，也不放可直接执行的完整解密代码；密钥只在运行时从 `key.dpapi` 解出，不进日志、报告或命令行。

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `CryptUnprotectData 失败（Win32 错误 5/13）` | 换了 Windows 账户，或该用户主密钥变了 | 必须用录制笔记的同一个用户；换账户无法导出，不要绕过 DPAPI |
| `key.dpapi 魔数不是 WTVSKEY1` / `... 不是 WTVSAES1` | 客户端升级改了容器格式 | 停止导出，重新逆向新格式；把看到的客户端版本报出来 |
| 手机上的录音在这台电脑找不到 | 只导出已同步到本机 `VoiceSummary` 的会话 | 在客户端里打开/同步那条录音，等它落盘后再导出 |
| 两个 `.enc` 正好 36 B | 空会话，客户端里本来就没内容 | 正常，计入「空壳」；现行工具不建目录（`01` 是 10-26 手工导出留下的旧目录） |
| 状态文件丢了 / 想重建 | 删了或损坏 | 正常导出一次就会重建；`--force` 只用于确实要重写文件（会改 mtime），通常不需要 |
| `最近一次同步.txt`、`NOTES.md` 比 `index.md` 旧 | 只有「有正文的新增/更新」才刷新快照；只多出空壳时不动 | 以 `--list` 和 `index.md` 为准，不要手改快照 |
| `0 新增 / 0 更新` | 没有新内容 | 正确结果，直接说没有；不要 `--force` |
| `注意：N 个目录在磁盘上但不在索引里` | 同步中断或在 App 里删过 | 报给用户，不要手改索引 |
| `未安装 python-docx` | 可选依赖缺失 | 只跳过 `recap.docx`，`transcript.txt` / `recap.html` 不受影响 |
| 日志出现 `watcher 异常退出` | 未预期异常（下一行带堆栈） | 后备任务仍会每 30 分钟补归档；把这两行日志报出来 |

## 7. 迁移到新机器

1. **复制两个目录**：技能目录 `C:\Users\SHiNe\.dsh\skills\wetype-voice-notes\`（脚本 + SKILL + 本 README）和导出目录 `C:\Users\SHiNe\Desktop\微信输入法录音笔导出\`（记录 + 索引 + 状态）。`_plain\` 是明文，按需决定是否带走。
2. **不要指望复制 `VoiceSummary` 就能解密**：`key.dpapi` 由 DPAPI 绑定用户（通常还绑定机器），换账户/换机器一般解不开。让新机器的微信输入法自己生成数据目录，重新录/同步即可；旧导出目录里的明文不受影响。
3. **准备运行环境**：`py -3` 可用即可；要 `.docx` 再装 `python-docx`（不装只少 Word 版）。
4. **重新安装钩子**：计划任务里存的是绝对路径，复制技能目录后必须重跑 `install-hook.ps1`；导出路径变了加 `-Out "新路径"`。然后 `status-hook.ps1` 确认 `0`。
5. 只想看旧档案、不自动归档：跳过第 4 步，直接用 `--out` 指向复制过来的导出目录即可。
